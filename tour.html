    פרק 2

    לולאת המשחק

    הדפדפן קורא לפונקציה frame בכל פעם שהמסך מוכן לתמונה חדשה (requestAnimationFrame). בדרך כלל זה 60 פעם בשנייה, במסך של 120Hz פי שניים. בכל קריאה: כמה זמן עבר, לעדכן את העולם, לצייר אותו.

    function frame(now):
    dt = (now - last) / 1000        // שניות מאז הפריים הקודם
    dt = clamp(dt, 0, 0.05)         // תקרה: אף פעם לא יותר מ-50ms
    switch state:                    // loading / title / play / pause / map
        case 'play':
            update(dt)               // הסימולציה: הכל זז קצת
            draw()                   // הציור: הכל מצויר מאפס
            drawHUD(); drawTouch()   // ממשק מעל העולם
    clearPressed()                   // "נלחץ בפריים הזה" מתאפס
    requestAnimationFrame(frame)     // תקרא לי שוב בפריים הבא
    למה להכפיל ב-dt? מחשבים שונים מציירים בקצב שונה. אם כל תנועה מוכפלת ב-dt, מכונית במהירות 120 יחידות לשנייה עוברת 120 יחידות בשנייה גם ב-30 פריימים וגם ב-144. ולמה תקרה? אם הטאב נתקע לשנייה, dt בלי תקרה היה מזיז הכל שנייה קדימה בצעד אחד, ומכוניות היו עוברות דרך קירות. עם התקרה המשחק פשוט מאט לרגע.

    גם מסך הטעינה הוא חלק מהלולאה: 9 שלבי בנייה (טקסטורות, מפה, כבישים, אנשים...) רצים אחד בכל פריים, כדי שפס הטעינה יתעדכן בין שלב לשלב במקום שהדף ייתקע.

    גרור את הקצב למטה. האדומה זזה צעד קבוע בכל פריים, אז היא מאטה ומאיצה עם הקצב. הכחולה מוכפלת ב-dt: תמיד באותה מהירות, אבל מתחת ל-20 פריימים היא קופצת. הצהובה היא המשחק: מוכפלת ב-dt עם תקרה, אז בקצב נמוך היא מאטה במקום לקפוץ.

    מה קורה בתוך update(dt), לפי הסדר

    1. envTick שעון יום ולילה, מזג אוויר
    2. introTips טיפים בדקה הראשונה
    3. interactTick מה אפשר ללחוץ עליו לידך (E)
    4. playerTick קלט ← תנועת השחקן או הרכב
    5. entitiesTick רכבים, אנשים, חיות, אוכלוסייה
    6. Farm.tick טרקטורים, גרירה, מטוס ריסוס
    7. Combat · FX · Pickups קליעים, חלקיקים, איסוף
    8. wantedTick רוגז ורודפים, מוסך, "שווה לנסות"
    9. Missions · Rampage משימות והשתוללויות
    10. camTick המצלמה רודפת אחרי השחקן
    11. UI · audio הודעות, רדיו, שמירה כל 60 שניות
    12. draw() קרקע, צללים, רכבים, אנשים, בניינים, תאורה
    בפועל כל זה קורה תוך פחות מ-16 אלפיות שנייה.

    פרק 3

    המצלמה

    המצלמה היא שלושה מספרים: x, y וזום. היא לא נצמדת לשחקן. בכל פריים היא סוגרת חלק קבוע מהמרחק אליו. זו החלקה אקספוננציאלית, ומשם מגיעה התחושה הרכה של התנועה.

    target = car.pos + car.velocity * lookAhead   // לאן שנוסעים, לא איפה שעומדים
cam.pos  += (target - cam.pos) * min(1, dt * 4.5)
zoomGoal  = 1.02 - min(0.36, speed / 650)     // מהר יותר = רואים יותר
cam.zoom += (zoomGoal - cam.zoom) * min(1, dt * 1.8)
shakeOffset = random() * G.shake              // רעידה במכה
G.shake *= exp(-7 * dt)                       // ודועכת לבד

    הנוסחה x += (target - x) * dt * k מופיעה במשחק עשרות פעמים: במצלמה, בהיגוי, באנשים שמסתובבים, בזום. היא זולה, יציבה, ונראית טבעית.

    • lookAhead: ‏0.15 שנייה ברגל, 0.42 ברכב, 0.9 במטוס. ככה רואים מה מגיע ולא את מה שכבר עברת.
    • במטוס הזום תלוי גם בגובה: 0.95 - alt * 0.28. ככל שעולים, רואים יותר מפה.
    • הזום מחושב מגודל המסך, כך שטלפון לרוחב וצג רחב רואים בערך אותו שטח.

    העיגול הצהוב הוא נקודת המטרה (הרכב + מהירות × מבט קדימה), והצלב הוא מרכז המצלמה. נסה היענות 20: המצלמה נצמדת ומרגישה נוקשה. נסה 1: היא מאחרת.

    פרק 4

    העולם כנתונים

    לשאלות "על מה אני עומד?" ו"במה אני עלול להיתקע?" יש שני מבנים שונים, כי הן נשאלות אלפי פעמים בשנייה וצריכות להיות זולות.

    רסטר חומרים

    כל המפה מחולקת לתאים של 8×8 יחידות: ‏480,000 תאים במערך בתים אחד. כל תא הוא מספר (דשא, כביש, חול, מים, חיטה...), ולכל חומר יש שורה בטבלה: אחיזה, גרר, האם זה דשא (עבירה!), האם זה מים (המנוע מוצף).

    matAt(x, y) = mat[floor(y / 8) * 800 + floor(x / 8)]   // חיבור וכפל. O(1)
MINFO[GRASS] = { grip: 0.8, drag: 0.86, lawn: true }
MINFO[SAND]  = { grip: 0.6, drag: 0.55 }
MINFO[WATER] = { grip: 0.4, drag: 0.25, water: true }

    גריד מרחבי

    בניינים נשמרים בתאים של 160 יחידות, חפצים (עצים, גדרות, ספסלים) בתאים של 128. כדי לדעת במה רכב נתקע, בודקים רק את התאים שהוא נוגע בהם, במקום לעבור על כל האובייקטים במפה.

    grid.query(box) -> רק מה שבתאים שהקופסה נוגעת בהם
for obj in grid.query(around car): test(obj)   // 5 בדיקות במקום 1,000

    גרף כבישים

    כל כביש הוא רשימת נקודות. הנקודות הופכות לצמתים, וקצוות כבישים נצמדים לצומת קרוב (עד 60 יחידות). על הגרף הזה נוסעים כל הנהגים במשחק (פרק 11).

    הזז את העכבר או האצבע על המפה. העיגול הכחול הוא "רכב". התאים הצהובים הם מה שנבדק, האובייקטים המסומנים הם המועמדים, והאדומים הם התנגשות אמיתית. הקרקע מאחור היא הרסטר עצמו, ברזולוציה של תא אחד לכל 8 יחידות.

    פרק 5

    התנגשויות: לדחוף החוצה

    אין פה מנוע פיזיקה. יש פונקציה אחת, shapePush: מקבלת עיגול וצורה (עיגול או מלבן מסובב) ומחזירה כיוון ועומק חדירה. דוחפים את העיגול החוצה בדיוק בעומק הזה, וזהו.

    רכב הוא שרשרת של עיגולים לאורכו: מכונית 2, מכלית חלב 3. עיגולים כי הבדיקה שלהם הכי פשוטה, ושרשרת כי רכב ארוך הוא לא עיגול.

    for circle in vehicle.circles:
    for b in bgrid.query(near circle):        // רק בניינים קרובים
        hit = shapePush(b, circle)            // { normal, depth } או null
        if hit:
            vehicle.pos += hit.normal * hit.depth

vn = dot(vehicle.velocity, normal)
if vn < 0:                                    // נסענו לתוך הקיר
    vehicle.velocity -= normal * vn * 1.3     // מבטלים ומקפיצים קצת אחורה
    impact(vehicle, -vn)                      // מעל 80: נזק. מעל 120: "בום"

    מלבן מסובב נבדק בטריק קלאסי: מסובבים את מרכז העיגול למערכת הצירים של המלבן, ושם המלבן ישר. הנקודה הכי קרובה היא clamp פשוט, והמרחק אליה הוא החדירה.

    חפצים נשברים לפי טבלה. לכל חפץ יש need ולכל רכב power. אם power ≥ need והמהירות מספיקה, החפץ נשבר במקום לחסום. טרקטור (4) מפיל עצים, אופניים (0) נעצרים בגדר. אין פה שורת קוד לכל צירוף: כלל אחד וטבלת מספרים.

    הזז את העכבר או האצבע. המכלית נוסעת לעברו ומנסה לעבור דרך הבניינים והעצים. החיצים האדומים הם הדחיפה (כיוון × עומק, מוגדל פי 3 שיהיה אפשר לראות). כשאין יד על המסך, היא נוסעת לבד בין נקודות.

    פרק 6

    פיזיקת רכב: למה זה מחליק

    הטריק של משחקי נהיגה מלמעלה: מפרקים את המהירות לשני רכיבים ביחס לכיוון הרכב. קדימה (vf) והצידה (vl). מנוע ובלמים משפיעים רק על קדימה. האחיזה "אוכלת" את הצידה. כשהאחיזה נמוכה (חול, בוץ, בלם יד), הרכיב הצידי שורד, והרכב מחליק.

    vf = dot(v, forward);   vl = dot(v, side)
grip = car.grip * ground.grip            // כביש 1, חול 0.6, בוץ 0.55
maxF = car.maxSpeed * ground.drag        // בחול אי אפשר להגיע למהירות מלאה
if gas:   vf += acc * dt * (1 - vf / maxF)
vl *= exp(-grip * (handbrake ? 0.18 : 1) * dt)   // האחיזה מחסלת החלקה
angle += steer * turn * dt * clamp(vf / 70, -1, 1)  // בעמידה לא מסתובבים
v = forward * vf + side * vl
if |vl| > 55 and |vf| > 50: skidMark()           // סימן צמיגים נצבע לקרקע
    • כל כלי הוא שורה בטבלה: מכונית מאיצה ב-270, טרקטור ב-150 עם אחיזה 12. אופניים מסתובבים ב-2.8, קומביין ב-1.15.
    • off אומר כמה הכלי אדיש לשטח: לטרקטור 1 (חול? לא מעניין אותו), למכונית 0.1.
    • במים: אחרי 1.2 שניות המנוע מוצף. טרקטור עובר.
    אותה בדיקה, שלוש מערכות. ה-matAt שקובע אחיזה גם מגלה שנסעת על דשא (רוגז: 0.32 לשנייה, פי 1.8 בכלי כבד), גם מגלה מים, וגם הופך שדה חיטה לאדמה כשדורסים אותו.

    ↑ גז, ↓ ברקס ורוורס, ←→ היגוי, רווח בלם יד. החץ הירוק הוא vf והאדום הוא vl. בלם יד בפנייה = דריפט. נסה את החול עם מכונית ואז עם טרקטור.

    פרק 7

    המטוס: גובה הוא רק מספר

    אין במשחק ציר Z. למטוס יש שדה אחד, alt, בין 0 ל-1. פיזיקת הטיסה היא כמה שורות: מעל 215 הוא עולה, מתחת הוא שוקע, וכשהגובה מגיע ל-0 זו נחיתה.

    on ground:                                  // כמו רכב רגיל
    if speed > 235 and gas: alt = 0.02      // "המראה!"
in air:
    goal = gas ? 440 : brake ? 150 : 290
    speed += (goal - speed) * dt * 0.45     // המהירות נמשכת ליעד
    if speed > 215: alt += 0.5 * dt         // עולה
    else: alt -= ((215 - speed) / 215 * 1.4 + 0.12) * dt
    if alt <= 0: touchdown()

    פרט נחמד שיצא מהנוסחה ולא תוכנן: על אדמה יבשה הגרר מגביל את המהירות ל-234, אז משדה אי אפשר להמריא. צריך מסלול.

    אז מה מונע ממנו לנחות על בניין?

    חצי ידני, חצי בחינם. בקוד יש שלושה חלקים:

    • באוויר הוא פשוט לא נבדק. if (alt > 0.05) skip מדלג על בניינים, על רכבים אחרים ועל הולכי רגל. ככה הוא עף מעל הכל. זו שורה ידנית.
    • מתחת ל-0.05 הוא "בגובה הקרקע". מערכת ההתנגשויות הכללית מפרק 5 חוזרת לפעול. אם הוא מנמיך לתוך בניין, הוא נהדף לקיר הקרוב ומקבל מכה, בדיוק כמו מכונית שנוסעת לקיר. את זה קיבלנו בחינם.
    • וברגע הנגיעה יש בדיקה מפורשת: בניין מתחת לגלגלים, או מהירות מעל 300, נותנים "נחיתה קשה!" ונזק של 90 ומעלה.
    מה גילינו כשבנינו את ההדגמה הזו: הבדיקה של "בניין מתחת לגלגלים" כמעט אף פעם לא מופעלת. בכל פריים המטוס יורד בערך 0.008 בגובה, אז הוא תמיד עובר דרך הטווח 0 עד 0.05, וההדיפה הכללית מוציאה אותו מהבניין עוד לפני שהוא נוגע. המנגנון הכללי פתר את המקרה לפני שהקוד הייעודי הגיע אליו. בנחיתות קשות, מה שבאמת עובד הוא תנאי המהירות.

    ועוד שורה אחת: לחיצה על E באוויר נותנת "אין מצנח! קודם לנחות".

    איך רואים גובה בלי תלת-ממד? הצל זז הצידה ככל שהמטוס עולה, והמטוס עצמו מצויר אחרי הבניינים, מוגדל ונדחף החוצה ממרכז המסך (פרק 8). המצלמה גם מתרחקת. שלושת אלה יחד, והמוח משלים "גובה".

    ↑ גז (המראה במסלול), ↓ האטה ונחיתה, ←→ היגוי. הכפתור הצהוב שם את המטוס באוויר מעל חדר האוכל ומנמיך אותו: בגובה 0.05 מערכת ההתנגשויות תופסת אותו והודפת אותו לקיר, ורק אז הוא נוגע בקרקע.

    פרק 8

    תלת-ממד מזויף

    הכל במשחק דו-ממדי. בניינים נראים בולטים כי הגג מצויר מוגדל, דחוף החוצה ממרכז המסך ביחס לגובה. בניין בקצה המסך נוטה החוצה, ובניין במרכז נראה מלמעלה, כמו שעין שמסתכלת למטה הייתה רואה. זה הטריק של GTA 2.

    k = 1 + height * 0.00125 * zoom       // כמה להגדיל את הגג
roof(p) = cam + (p - cam) * k         // כל פינה נדחפת החוצה מהמרכז
for each wall edge (a, b):
    fill quad(a, b, roof(b), roof(a)) // קיר = מרובע בין הבסיס לגג
fill polygon(roof(corners))           // והגג מעל

    הקירות שפונים למצלמה מוסתרים אוטומטית: הגג נדחף מעליהם. נשארים רק הקירות שפונים החוצה, וזה בדיוק מה שהיינו רואים במציאות. אין פה חישוב "מה נראה". זה יוצא מהגאומטריה.

      מערכות שמתנגשות זו בזו. אף אחד לא כתב את הסיפור הבא. הוא נוצר מהחיבור:

      נסעת על הדשא←רסטר: lawn←ותיק במרחק 200 ראה←רוגז, כוכב שני←קלנועיות יוצאות←ברחת לשדה←הקלנועית נתקעה בחול←מוסך

      כל חוליה היא מנגנון כללי מפרק אחר. כשהם מחוברים נכון, השחקן ממציא את הסיפורים לבד. זה ההבדל בין משחק לבין רשימת פיצ׳רים.

      לחץ על המסך או על "אגרוף". אחר כך "הכל כבוי" ונסה שוב: אותה מכה בדיוק, אותו נזק, תחושה של גיליון אלקטרוני.
